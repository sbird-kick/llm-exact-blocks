# DATA: what training data this repository ships, and what it does not

Every data file here is plain JSON lines, one row per line, each file under 25 MB, listed with its md5. Nothing here
is an evaluation set, a held-out fold, a hidden-state dump or a model weight.

| what | where | rows | size | details |
|---|---|---|---|---|
| bank templates + generators (all banks) | `banks/` | regenerated by the make scripts | small | `banks/README.md` |
| generated bank rows (subrole, divrole2, v5x C1-C6, v5div, v6ms closed rounds) | `data/banks/` | 114,220 in 29 files | 308 MB (uncompressed) | `data/DATA_banks.md`: per file source, languages, rows, bytes, md5, generator md5, fold columns, license |
| real word problems (wild rows) | not shipped yet | - | - | below |

`python banks/make_bank_data.py` checks every shipped row file against `data/banks/ROWS.md5`.

## Using bank rows with `defuse/`

Bank rows name their fields differently from the def-use rows; `defuse/bank_rows.py` adapts them without touching
the text or the answer, and assigns `fold` from a bank fold column you choose (one value held out as fold 5):

```python
from defuse.bank_rows import to_defuse_row
row = to_defuse_row(bank_row, fold_key=("v6", "tmpl_fold"), heldout_value=5)        # v6ms: held-out templates
row = to_defuse_row(bank_row, fold_key=("v6", "lang_fold"), heldout_value=5)        # v6ms: held-out languages
row = to_defuse_row(bank_row, fold_key="fold", heldout_value=4, values=(0, 1, 2, 3, 4))   # subrole / divrole2
```

The project used v6ms with a rotation (each language block held out once); a single fixed held-out value is the
simple version of that. The v6ms rounds G1 (chains) and G3 (varied question types) carry an infix equation and parse
exactly; the G2 rounds (conditionals, selection) carry their program only in `v6.program` (with guards), which the
def-use grammar does not express, so the parser reports `no_equation` for them (10,638 of the 31,716 shipped
at-most-5-numeral v6ms rows).

## Wild training rows (real word problems): not included yet

The def-use readers in the project were fitted on folds 1-4 of a pool of public word problems with gold equations.
Those rows are **not in this repository yet**; the project lead decides when and which. When they arrive they will
follow these rules, and `defuse/data.py` already enforces the fold part:

* **Folds 1-4 only.** Fold 5 (the held-out fold) and fold 6 (the source datasets' official test / validation splits
  and every row linked to them) are never shipped, and the loader refuses any row whose `fold` is 5 or 6. Rows from
  a source's own dev or test split are left out even when they sit in folds 1-4.
* **Only sources whose license and train/test status are clear.** From the project's source notes:

  | source | license (as stated by the source) | status for this repo |
  |---|---|---|
  | MathQA | Apache-2.0 | eligible: train split only, folds 1-4 |
  | ASDiv | CC BY-NC 4.0 (non-commercial, attribution) | eligible: no official test split; folds 1-4; the NC license travels with the file |
  | MAWPS | none stated; the original site is offline | left out |
  | Math23K | none stated (the copy used is a third-party repository) | left out |
  | Ape210K | the repository's README gives a license for the code only, none for the data | left out |
  | GSM8K train | MIT | not in the def-use fit pool (the project never fitted the def-use readers on it) |

* **Layout:** `data/wild/<source>/fold<k>.jsonl`, plain JSON lines, each file under 25 MB, one row per problem with
  the fields `defuse/` reads (`row_id`, `fold`, `text`, `annotation`, `numerals_written`, `prov`, `gold_frac`,
  `status`), the gold-program labels, and the project's Qwen3 host-outcome labels (host right / host silent) only
  as clearly named, Qwen-specific columns. Never hidden-state dumps (they are tens of gigabytes; you make your own
  with `defuse/dump.py`).
* **Git:** `.gitignore` ignores everything under `data/` except `data/banks/`; when wild rows arrive, add
  `!data/wild/` and `!data/wild/**/*.jsonl` to it, or git will silently skip them.
* **Never:** any evaluation or held-out set (the GSM8K test family, MGSM, AfriMGSM, SVAMP, the project's fresh
  held-out set), and no bank that is still being generated.

Until then, train and test the pipeline on the synthetic banks below, with folds assigned by template.
